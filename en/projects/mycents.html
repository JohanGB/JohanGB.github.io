01Problem

Local-first personal finance: each environment is a SQLite file on the device, and Google Drive only receives a copy when switching environments or closing the app. One codebase (Flet) for Windows and Android.

02Data

  • The user's expenses in SQLite, with money stored as integer cents and converted with Decimal; float is rejected.
  • For performance: a synthetic database with 1,000,000 expenses over 10 years (104 MB).

03Method

  • MVC architecture: the controller does not import Flet and is tested on its own.
  • Analytics with GROUP BY on a covering index, never Pandas.
  • Read-only enforced by SQLite (mode=ro, query_only=ON); editing requires a 5-minute session.
  • Sync never merges: it compares the local fingerprint with Drive's headRevisionId; if both changed, nothing is overwritten and the user chooses.
  • drive.file as the only permission; the token is stored in the OS credential store.

04Validation

  • Full monthly view: 11 ms with a covering index vs. 1,133 ms and 364 MB loading everything into pandas (7,386 rows in Python vs. 1,000,000).
  • Atomic downloads validated with MD5, integrity_check, foreign_key_check and environment id.
  • A test proves new and migrated schemas are identical.
  • Windows and sync were tested against real Google Drive. 195 automated tests.

05Limitations

  • The .db file is not encrypted yet: the PIN protects the app, not the file.
  • Android has not been tested on a physical phone.
  • Drive API v3 has no conditional upload, so a narrow last-writer-wins race exists (Drive keeps about 30 days of revisions).
  • One open .db per device: no concurrent multi-user merge.
